# iOS production build runbook

How to produce and upload a Logdit App Store build from a local machine.

There is no `eas.json` and no cloud build. `apps/mobile/ios/` and
`apps/mobile/android/` are **gitignored and untracked** — they are generated by
`expo prebuild` and archived locally in Xcode. That single fact drives most of
this document:

> **Any native change that must survive has to live in a config plugin.**
> Edits made directly in `ios/` are destroyed by the next `--clean` prebuild.
> The two plugins in `apps/mobile/plugins/` exist for exactly this reason.

All commands run from `apps/mobile` unless stated otherwise.

---

## 0. One-time machine setup

Only needed on a new laptop, or after a macOS/Xcode reinstall.

```bash
# Xcode must be signed into the Apple Developer account for team D766Z89ML4.
# Xcode → Settings → Accounts → "+" → Apple ID.

# Confirm signing identities exist AND carry their private keys.
security find-identity -v -p codesigning
# Expect at least one "Apple Distribution: ..." entry. Certificates migrated
# without their private keys will not appear here.
```

Sentry CLI auth — sourcemap upload runs as part of the Release build phase:

```bash
# Create at https://de.sentry.io → Settings → Auth Tokens.
# Scopes needed: project:releases, org:read
printf 'auth.token=YOUR_TOKEN_HERE\n' > ~/.sentryclirc
chmod 600 ~/.sentryclirc
```

> Keep the token in `~/.sentryclirc`, never in `.env.production`. That file is
> git-tracked and the repo is public; only `EXPO_PUBLIC_*` values (which are
> baked into the JS bundle and are not secret by design) belong in it.

## 1. Bump the version

Edit `apps/mobile/app.json`:

- `expo.version` — the user-facing marketing version (e.g. `1.0.0`).
- `expo.ios.buildNumber` — **must increase on every upload**, even when
  re-uploading an otherwise identical binary. App Store Connect rejects
  duplicates.

Current state: `1.0.0` / build `10`.

---

## 2. Build the workspace packages

`apps/mobile` consumes `@acme/shared` and `@acme/api-client` from their compiled
`dist/` output. Skipping this bundles whatever was compiled last, which may
predate your changes.

```bash
# from the repo root
pnpm install
pnpm build
```

---

## 3. Prebuild

Regenerates `ios/` from `app.json` plus the config plugins.

### Without `--clean` (default — prefer this)

```bash
npx expo prebuild --platform ios
```

Applies config plugins over the **existing** `ios/` directory. Faster, and
preserves anything set manually in Xcode — notably the signing team on the Debug
configuration. Use this for routine builds.

### With `--clean`

```bash
npx expo prebuild --platform ios --clean
```

**Deletes and regenerates `ios/` from scratch.** Use only when:

- you changed native config in `app.json` (plugins, permissions, deployment
  target, bundle identifier, background modes),
- you added or removed a native dependency,
- the build is failing in a way that smells like stale native state.

**After a `--clean` prebuild the Debug configuration's signing team resets**
(historically to `ZNR4ZAPKNR`). Release picks up `ios.appleTeamId` from
`app.json`, so archives are unaffected, but `npx expo run:ios --device` will fail
on signing until the team is set back to `D766Z89ML4` in Xcode.

### Both platforms

`pnpm prebuild` / `pnpm prebuild:clean` run without `--platform` and regenerate
**iOS and Android**. Pass `--platform ios` (or `-p ios`) to scope to iOS, as
above.

CocoaPods installs automatically as part of prebuild. To redo just that step:

```bash
cd ios && pod install && cd ..
```

## 4. Verify before archiving

Four checks, all cheap. Run them every time.

### 4a. Production API URL is wired in

```bash
grep -A3 'with-production-node-env BEGIN' ios/.xcode.env
```

Expected:

```
# >>> with-production-node-env BEGIN
if [[ "$CONFIGURATION" != *Debug* ]]; then
  export EXPO_PUBLIC_API_URL=https://api.logdit.app/api
fi
```

**This is a presence check, not a selection check.** The plugin writes that block
unconditionally; the switch is the `$CONFIGURATION` shell guard, which Xcode
evaluates at build time. You are confirming the block exists — not that
"production is selected", since nothing in this file differs between build types.

The block exists because `@expo/env` never overrides an already-set variable, so
a stale dev `EXPO_PUBLIC_API_URL` in the environment would otherwise be baked
into the release bundle — producing the iOS local-network prompt and "network
request failed" against an unreachable `192.168.x` address.

Missing block means the plugin didn't run: re-run prebuild.

### 4b. No background audio entitlement

```bash
grep -A4 UIBackgroundModes ios/Logdit/Info.plist
```

**Expect no output.** `expo-audio` defaults `enableBackgroundPlayback` to `true`,
which injects `UIBackgroundModes: ['audio']`. Nothing in the app records while
backgrounded, and an unjustified background mode invites rejection under
Guideline 2.5.4 — so `app.json` pins it to `false`. Any output here means that
setting was lost.

### 4c. Sentry CLI can authenticate

```bash
SENTRY_PROPERTIES=ios/sentry.properties npx sentry-cli info
```

Expect it to resolve `Default Organization: logdit-ltd` and
`Default Project: logdit-mobile`. That resolution succeeding is the real signal —
it can only work by reaching the correct org.

You will also see:

```
WARN Using https://sentry.io (embedded in token) rather than manually-configured
     URL https://de.sentry.io/
```

**This warning is expected and harmless.** Sentry splits `sentry.io` — the
*control silo*, holding org and auth metadata, identical for every org regardless
of region — from `de.sentry.io`, the EU *data region* where events and artifacts
actually live. An org token legitimately carries both: `url` for the control silo
and `region_url` for the region. The CLI compares the control URL against
`defaults.url`, which is set to the region URL, and flags the mismatch. Ignore it.

To confirm a token's region, decode its payload locally:

```bash
python3 -c "import base64,sys;print(base64.b64decode(sys.argv[1].split('_')[1]+'==').decode())" \
  "$(grep -o 'sntrys_[^ ]*' ~/.sentryclirc)"
# expect: "region_url":"https://de.sentry.io"
```

### 4d. Signing team

In Xcode, confirm the **Release** configuration's team is `D766Z89ML4`.

---

## 5. Archive

```bash
open ios/Logdit.xcworkspace
```

Always the **`.xcworkspace`**, never the `.xcodeproj` — the latter misses the
CocoaPods targets.

In Xcode:

1. Scheme: **Logdit**
2. Destination: **Any iOS Device (arm64)**. Archive is disabled while a simulator
   is selected.
3. **Product → Archive**
4. Wait. This runs the release bundle (`expo export:embed`) and the Sentry
   sourcemap upload, so it is materially slower than a debug build.

---

## 6. Upload

In the Organizer window that opens on success:

1. Select the new archive; confirm the version and build number.
2. **Distribute App → App Store Connect → Upload**
3. Accept the default signing options (automatic).
4. Upload.

Processing in App Store Connect takes roughly 5–30 minutes before the build
becomes selectable for TestFlight or a release.

---

## 7. After upload

- **Sentry**: at `de.sentry.io` → `logdit-mobile` → **Releases**, confirm a
  release exists for this build with artifacts attached. No artifacts means crash
  reports won't symbolicate, which defeats the point of the upload step.
- **TestFlight**: install and smoke-test on a real device before submitting.
- **Landing site**: the App Store listing links to `logdit.app`, and the app links
  to the privacy and terms pages from Settings. Deploy the site alongside the
  release — see [landing-deploy.md](../production/landing-deploy.md).

## Troubleshooting

### `No Account for Team "D766Z89ML4"` / `No signing certificate found`

Xcode isn't signed into the developer account. Certificates and Xcode *accounts*
migrate separately between machines — `security find-identity` can list valid
identities while Xcode still has no account configured. Fix in
Xcode → Settings → Accounts.

### `Auth token is required for this request` from sentry-cli

`~/.sentryclirc` is missing, empty, or holds an expired token. Re-run the setup in
§0. Note the file lives in your **home** directory, not the repo.

### Release build hits a `192.168.x` address, or prompts for local network access

The `.xcode.env` block from §4a is missing. Re-run prebuild and re-check.

### Archive is greyed out

The destination is a simulator. Switch to **Any iOS Device (arm64)**.

### `npx expo run:ios --device` fails on signing after a clean prebuild

Expected — see §3. Set the Debug configuration's team back to `D766Z89ML4`.

### Duplicate build number rejected on upload

`expo.ios.buildNumber` wasn't incremented. Bump it, re-run prebuild, re-archive.
